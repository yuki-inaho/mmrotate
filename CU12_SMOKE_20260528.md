## Required change candidates surfaced

This fork's `main` is `mmrotate v0.3.4`. v0.3.4 hard-asserts `mmcv 1.5.3..1.8.0`
and `mmdet 2.25.1..<3.0.0`, which makes cu12 + mmcv 2.x + mmdet 3.x impossible
without a wholesale code migration.

### Changes applied in this branch (so cu12 smoke passes)

1. Branch base reset from `main` (v0.3.4, commit `b030f38`) to upstream
   `1.x` HEAD (commit `d50ab76`, `[Fix] Fix nan loss in RotatedIoULoss`).
   This switches the package source from the 0.x API tree to the 1.x API
   tree, which already uses `mmcv 2.x` / `mmdet 3.x` / `mmengine` APIs.

2. `mmrotate/__init__.py:30`
   - Before (upstream 1.x): `mmdet_maximum_version = '3.1.0'` (with `<=`).
   - After (this branch): `mmdet_maximum_version = '3.4.0'` (with `<`).
   - Rationale: `mmrotate 1.0.0rc1` was published while `mmdet` was still on
     the 3.0/3.1 line. Newer `mmdet` (3.2 / 3.3) is the only line that pairs
     with `mmcv 2.1.0+`, which is the lowest `mmcv` whose cu121 wheel is
     published. Without this relaxation `import mmrotate` aborts on
     `AssertionError: MMDetection 3.3.0 is incompatible with MMRotate 1.0.0rc1`.
